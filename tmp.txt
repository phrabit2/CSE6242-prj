### 5.2 vLLM — 추론/서빙

| 항목 | 내용 |
|---|---|
| 이미지 | `vllm/vllm-openai` (⚠️ 실제 태그 확인 필요) |
| 포트 | 8000 (OpenAI 호환 API) |
| 기동 스크립트 | `~/vllm/start_vl.sh` |

```bash
sudo docker run -d --name vllm \
  --gpus all --ipc=host \
  -v /data/ai-models:/models \
  -p 8000:8000 \
  -e HF_HUB_OFFLINE=1 -e TRANSFORMERS_OFFLINE=1 \
  vllm/vllm-openai:<버전> \
  --model /models/Qwen2.5-VL-7B-Instruct \
  --served-model-name qwen2.5-vl \
  --gpu-memory-utilization 0.28 \
  --max-model-len 16384 \
  --limit-mm-per-prompt '{"image":2,"video":0}' \
  --trust-remote-code
```

**실제 활용 내용**
- Qwen2.5-VL-7B zero-shot 베이스라인 확보 (파인튜닝 전 성능 비교 기준)
- `--gpu-memory-utilization 0.28` — **의도적으로 28%만 점유.** 나머지를 학습용으로 남겨 학습·서빙 동시 운용
- `--limit-mm-per-prompt` — 멀티모달 입력 시 프롬프트당 이미지 2장 상한
- LoRA 어댑터 서빙 시 `--enable-lora` 옵션으로 **베이스 vs 파인튜닝 A/B 비교** 가능

**주의**
- 컨테이너명 충돌 시: `sudo docker rm -f vllm` 후 재실행
- 에어갭이므로 `HF_HUB_OFFLINE=1` 필수 (미설정 시 HuggingFace 접속 시도로 기동 실패)
- 모델 로딩에 1~3분 소요. `Application startup complete` 로그 확인 후 사용

**Docker를 쓴 이유** — 호스트 conda base의 `transformers 5.12.1`이 LLaMA-Factory 요구 상한(`≤5.8.0`)을 초과하여 의존성 격리가 필요했음. 호스트 환경은 변경하지 않음.

```bash

  --gpus all --ipc=host \
  -p 7860:7860 \
  -v /data/ai-models:/models \
  -v /data/sample_train:/data/sample_train \
  -v /data/llamafactory/output:/output \
  -v /data/llamafactory/dataset_info.json:/app/data/dataset_info.json \
  -e GRADIO_SERVER_NAME=0.0.0.0 -e GRADIO_SERVER_PORT=7860 \
  -e HF_HUB_OFFLINE=1 -e TRANSFORMERS_OFFLINE=1 \
  hiyouga/llamafactory:latest \
  llamafactory-cli webui
```

**볼륨 마운트 규칙**

| 호스트 | 컨테이너 | 용도 |
|---|---|---|
| `/data/ai-models` | `/models` | 베이스 모델 |
| `/data/sample_train` | **`/data/sample_train`** | 학습 데이터 — **호스트와 동일 경로 유지** |
| `/data/llamafactory/output` | `/output` | 산출물 |
| `/data/llamafactory/dataset_info.json` | `/app/data/dataset_info.json` | 데이터셋 등록 |

> ⚠️ 학습 데이터 경로를 컨테이너와 다르게 잡으면 **JSON 안의 이미지 경로가 깨져 로드 실패**합니다. 반드시 동일 경로로 마운트.

**데이터셋 등록** (`dataset_info.json`)

**학습 실행**
```bash

# WebUI: 7860 터널링 후 Model path 에 /models/Qwen2.5-VL-7B-Instruct 직접 입력
```

**학습 설정 및 결과 (실제 수행분)**

| 항목 | 값 |
|---|---|
| 모델 / 템플릿 | Qwen2.5-VL-7B-Instruct / `qwen2_vl` |
| stage / type | sft / **lora** |
| lora_target | `all` (언어 레이어 7종, 비전 타워 제외) |
| batch / grad accum | 2 / 8 (**실효 배치 16**) |
| epochs / LR | 3 / 1e-4 (cosine) |
| precision | bf16 |

## 6. ★ 커스텀 PyTorch 배치 벤치마크 (핵심 실험)

### 6.1 실험 목적

파인튜닝 기법·배치 크기별 **GPU/CPU 자원 소모량과 시간**을 측정.
**모델 성능(정확도) 측정이 아니라 리소스 프로파일링이 목적**이며, A100 80GB에서 사용 가능한 최대 배치 크기를 실측으로 찾는 것이 최종 목표.

### 6.2 실험 조건 (고정 변수)

| 항목 | 값 | 비고 |
|---|---|---|
| 모델 | Qwen2.5-VL-7B-Instruct | |
| 데이터 | 200장 (파손 Y/N) | 초기 예비실험은 20장 |
| epochs | **3 고정** | `--epochs` 인자 미지정 시 default=3 |
| gradient accumulation | **1 고정** | LLaMA-Factory(GA=8)와 조건 다름 |
| `MAX_PIXELS` | `512*28*28` | **이미지 토큰 수 = VRAM 직결. 전 기법 동일 고정 필수** |
| gradient checkpointing | 활성화 | `enable_input_require_grads()` 동반 필수 |
| loss 마스킹 | 프롬프트 `-100` 마스킹 | 정답 토큰만 학습 |
| 변수 | **batch size만 변경** | |

> **Trainer 미사용, 커스텀 학습 루프 채택 이유**: `bench.start_train()`/`end_train()`으로 학습 구간을 정확히 감싸 **모델 로딩 시간을 제외한 순수 학습 시간**만 측정하기 위함.

### 6.3 측정 도구 3종

| 도구 | 측정 항목 | 출력 |
|---|---|---|
| `bench.py` | peak VRAM (torch allocated/reserved), 파라미터 수, step/throughput | `results.csv` |
| `monitor.sh` | nvidia-smi 기반 GPU/CPU 시계열 | `gpu_log.csv`, `cpu_log.csv` |
| `/usr/bin/time -v` | wall-clock, 최대 RSS(CPU 메모리) | `time.txt` |

> `bench.py`의 `peak_vram_alloc_gb`(PyTorch가 텐서에 쓴 양)와 `nvidia-smi`의 `memory.used`(예약분 포함 실제 점유)는 관점이 다릅니다. **"80GB 중 얼마나 차는가"는 nvidia-smi 값이 현실적**입니다.

### 6.6 결과 해석 기준

1. **peak VRAM이 80GB의 80~90%(64~72GB)에 닿는 batch = 안전한 최대치.** 100% 근접은 불안정·OOM 위험
2. **OOM이 발생한 batch의 바로 아래가 실전 상한.** OOM은 실패가 아니라 **찾고자 한 경계선**
3. **`samples_per_sec`이 정체되는 지점 = 효율 최적점.** 그 이상은 VRAM만 소모하고 속도 이득 없음
4. 배치별 시간 비교는 `sec_per_step`이 아니라 **`total_time_s`로** 해야 공정 (batch가 크면 step 수가 줄기 때문)

### 6.7 ⚠️ 실험 시 반드시 알아야 할 함정 2가지

**함정 ①. batch_size 인자가 반영되지 않는 케이스 — 실제 발생**

`--batch_size`를 넘겨도 코드 내 `BATCH_SIZE` 하드코딩이 남아 있으면 인자가 무시됩니다.
5회 실행이 전부 batch=3으로 돌았음에도 에러 없이 완주하여 **발견이 늦어졌습니다.**

**검증법**: `num_steps`를 확인하십시오. 6.5의 산식과 일치하지 않으면 인자가 안 먹힌 것입니다.
`num_steps`와 `peak_vram`이 배치를 바꿔도 동일하다면 100% 이 문제입니다.

```bash
grep -n "batch_size\|BATCH_SIZE\|add_argument" src/train_lora.py
```

**함정 ②. outputs 폴더에 로그만 생기고 어댑터가 없는 케이스 — 실제 발생**

`outputs/lora_bN/`에 `time.txt`, `cpu.csv`, `gpu.csv`만 있고 `.safetensors`·`tokenizer.json`이 없다면,
**학습 루프가 `model.save_pretrained()` 도달 전에 종료된 것**입니다.

- 로그 3종은 `monitor.sh`·`/usr/bin/time`이 **학습 스크립트 바깥에서** 만들므로 학습이 실패해도 생성됨
- 어댑터 파일은 학습이 **끝까지 완주해야만** 생성됨
- → `results.csv`에 행이 추가됐는지로 완주 여부를 먼저 판별

**함정 ③. stderr 리다이렉트로 에러가 숨는 현상**

`2> outputs/.../time.txt`로 stderr를 파일에 돌리므로 **Python traceback이 터미널에 안 보입니다.**
"에러가 없었는데 결과가 없다"면 반드시 `cat time.txt`로 traceback을 확인하십시오.

## 7. 프로젝트 배경 및 진행 상태

**과제**: 물류 파손 박스 판별 VLM 파인튜닝 (검수 스테이션 적용 목표)

**5단계 커리큘럼 진행 현황**

| Phase | 내용 | 상태 |
|---|---|---|
| 0 | 평가 하네스 · 데이터 준비 (`manifest.csv` 기반 고정 테스트셋) | 완료 |
| 1 | ResNet50 전이학습 이진 분류 베이스라인 | ⚠️ 확인 필요 |
| 2 | VLM zero-shot 베이스라인 + 프롬프트 엔지니어링 | 완료 (vLLM) |
| 3 | **VLM LoRA/QLoRA SFT** | 완료 (LLaMA-Factory) |
| 4 | 양자화 · 서빙 최적화 | 미착수 |
| 5 | 에이전트 · RAG 통합 | 미착수 |

> 설계 원칙: 전 Phase가 **단일 고정 테스트셋(`manifest.csv`)**을 공유하여 단계 간 직접 비교가 가능하도록 구성됨.
