원인 나왔어. java.net.UnknownHostException: pinot-controller — pinot-init이 pinot-controller라는 이름을 못 찾고 있어. 즉 테이블 생성 시도는 하는데 controller에 접속을 못 해서 7개 다 실패한 거야. 그래서 /tables가 비어있는 거고.

왜 이름을 못 찾나

--force-recreate pinot-init 하나만 재생성했잖아. 그런데 pinot-init은 컴포즈가 만든 네트워크 안에서 pinot-controller라는 서비스명으로 DNS를 찾아야 하는데 — 단독으로 up하면 다른 컨테이너들과 같은 네트워크에 제대로 안 붙거나, controller가 그 시점에 준비가 안 됐을 수 있어. 게다가 pinot-init은 원래 depends_on: pinot-broker-0 조건으로 순서를 기다리는데, 단독 실행은 그 순서를 무시해.

해결 — controller 준비 확인 후, 네트워크 붙여서 재실행

1. controller가 실제로 살아있고 이름이 붙는지 먼저 확인:

bash
# controller 컨테이너에서 자기 이름이 해석되는지
sudo docker exec pinpoint-docker-pinot-controller-1 curl -s http://localhost:9000/health

앞서 재시작한 controller가 Up 18 seconds였으니 지금쯤 완전히 떴을 거야. OK나 정상 응답이 나오면 controller는 준비된 거야.

2. pinot-init을 전체 스택 맥락에서 재실행:

핵심은 같은 네트워크에 확실히 붙이는 것이야. run으로 네트워크를 명시해서 스키마를 직접 등록하는 게 제일 확실해:

bash
cd /data/pinpoint/pinpoint-docker
sudo docker compose -f docker-compose.yml -f docker-compose-metric.yml up -d --force-recreate --no-deps pinot-init
sleep 5
sudo docker logs pinpoint-docker-pinot-init-1 --tail 30

여전히 UnknownHostException이 나면 네트워크 문제가 확실하니, controller의 실제 컨테이너명으로 직접 붙여서 실행:

bash
# controller가 붙어있는 네트워크 확인
sudo docker inspect pinpoint-docker-pinot-controller-1 --format '{{range $k,$v := .NetworkSettings.Networks}}{{$k}}{{end}}'

나온 네트워크명(예: pinpoint-docker_pinpoint)으로 pinot-init을 수동 실행:

bash
sudo docker run --rm \
  --network pinpoint-docker_pinpoint \
  -v /data/pinpoint/pinot-schemas:/schemas:ro \
  apachepinot/pinot:1.0.0-11-amazoncorretto \
  sh -c 'cd /tmp && cp /schemas/*.json . && sed -i "s/localhost:19092/pinpoint-kafka:9092/g" *.json &&
  for t in uriStat tag double dataType exceptionTrace inspectorAgent inspectorApplication; do
    /opt/pinot/bin/pinot-admin.sh AddTable -schemaFile ${t}Schema.json -tableConfigFile ${t}Table.json -controllerHost pinot-controller -controllerPort 9000 -exec || true
  done'

이건 pinot-init이 하던 걸 네트워크를 명시해서 직접 돌리는 거야. pinot-controller 이름이 그 네트워크 안에서 해석되니 이번엔 붙을 거야.

3. 테이블 생성 확인:

bash
curl -s http://localhost:9000/tables

이번엔 uriStat, tag, double, dataType, exceptionTrace, inspectorAgent, inspectorApplication 7개가 나와야 해.

데이터 유실에 대해

테이블 정의(스키마)는 재생성으로 복구되지만, 그동안 쌓였던 Inspector 지표 데이터는 사라졌어. data-root 이전 과정에서 pinot 볼륨 데이터가 날아간 거야. 다만:

트레이스·서버맵·콜스택(HBase)은 멀쩡해 — 이건 /data/pinpoint/hbase에 bind돼 있었으니 안전
Inspector 지표는 앞으로 다시 쌓여 — agent들이 계속 보내니까 테이블만 만들면 새 데이터가 채워짐
과거 지표 히스토리만 잃은 거라, 운영 모니터링엔 큰 지장 없어
