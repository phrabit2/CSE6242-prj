
범인 정확히 나왔어. docker ps -a에서 controller의 실제 이름을 봐:

8fac889f86ec  ...  b6014b1f0498_pinpoint-docker-pinot-controller-1

controller 컨테이너 이름 앞에 b6014b1f0498_ 해시가 붙어있어. 이건 우리가 여러 번 겪은 그 좀비 흔적이야 — 예전에 v1/재생성 실패로 컨테이너가 임시 개명된 거지. 이게 왜 문제냐면:

도커 DNS는 컨테이너의 "네트워크 별칭"으로 이름을 해석하는데, 이 controller가 좀비 상태라 pinot-controller라는 별칭이 제대로 안 붙어 있어. 그래서 pinot-init이 pinot-controller를 찾아도 DNS가 응답을 못 하는 거야. UnknownHostException의 진짜 원인이 이거야.

b5bdc5f9b840_pinpoint-docker-pinpoint-kafka-1도 같은 좀비고. controller 재시작할 때 이 좀비가 정리 안 된 채 재시작만 돼서 별칭이 깨진 상태로 남은 거야.

해결 — 좀비 controller를 제대로 재생성

restart가 아니라 삭제 후 새로 생성해야 별칭이 제대로 붙어. 정상 이름으로 다시 만드는 거야.

bash
cd /data/pinpoint/pinpoint-docker

# 1. 좀비 controller와 kafka 제거
sudo docker rm -f b6014b1f0498_pinpoint-docker-pinot-controller-1
sudo docker rm -f b5bdc5f9b840_pinpoint-docker-pinpoint-kafka-1

# 2. compose로 재생성 (정상 이름 + 별칭으로 새로 뜸)
sudo docker compose -f docker-compose.yml -f docker-compose-metric.yml up -d

# 3. 이름이 정상화됐는지 확인 (해시 프리픽스 없어야 함)
sudo docker ps --format '{{.Names}}' | grep -E 'pinot-controller|kafka'

3번에서 pinpoint-docker-pinot-controller-1이 해시 없이 나오면 별칭이 제대로 붙은 거야.

그다음 — DNS 해석 확인 후 pinot-init

controller 이름이 정상화되면, 다른 컨테이너에서 pinot-controller가 해석되는지 먼저 확인:

bash
sudo docker exec pinpoint-collector getent hosts pinot-controller

IP가 나오면 DNS 정상. 그때 pinot-init 재실행:

bash
sudo docker compose -f docker-compose.yml -f docker-compose-metric.yml up -d --force-recreate --no-deps pinot-init
sleep 10
sudo docker logs pinpoint-docker-pinot-init-1 --tail 40

이번엔 UnknownHostException 없이 AddTable이 7개 성공해야 해. 그다음:

bash
curl -s http://localhost:9000/tables
⚠️ 재생성 시 주의 — HBase 좀비

up -d로 전체를 재수렴할 때 HBase도 건드려질 수 있어. 우리가 그렇게 고생한 HBase(/data/pinpoint/hbase bind, 22개 테이블)가 재생성되면서 또 Master 초기화 이슈가 날 수 있으니, 2번 up -d 후에 HBase 상태를 꼭 확인:

bash
sudo docker ps --format '{{.Names}}' | grep hbase       # 해시 프리픽스 없이 pinpoint-hbase 인지
sudo docker exec pinpoint-hbase jps                      # HMaster 살아있는지

HMaster가 사라지면 아까 그 ZK 초기화 대신, 이번엔 데이터가 살아있으니 그냥 재시작만으로 복구될 가능성이 높아 (테이블이 이미 /data에 있으니). 그건 상태 보고 판단하자.

핵심은 — pinot-init의 네트워크 문제가 아니라, controller가 좀비라 pinot-controller 이름이 안 붙는 것이었어. 좀비 2개(b6014... controller, b5bdc... kafka)를 rm -f하고 up -d로 정상 재생성하면 이름이 붙고, 그러면 pinot-init이 붙을 수 있어.

먼저 좀비 2개 제거 → up -d → controller 이름 정상화 확인까지 하고, 그 결과랑 HBase 상태(jps) 알려줘. 좀비만 걷어내면 나머지는 순조로울 거야.
