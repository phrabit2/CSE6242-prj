## 4. ⚠️ 운영 시 반드시 알아야 할 3가지

### 4.1 Docker Compose 버전이 88번 서버와 다름

| 서버 | Compose | 명령 |
|---|---|---|
| **10.194.178.89 (본 서버)** | **v1 (1.29.2)** | `sudo docker-compose` (**하이픈**) |
| 10.194.178.88 (Pinpoint) | v2 | `sudo docker compose` (스페이스) |

- v1은 최신 Docker 이미지와 호환되지 않아 `KeyError: 'ContainerConfig'` / `KeyError: 'id'` 오류 발생
- **일부 컨테이너는 `docker run`으로 기동**되어 있어 `docker-compose restart` 시 `No containers to restart` 반환
- → **개별 컨테이너 제어 권장**

```bash
sudo docker restart prometheus
sudo docker restart grafana
sudo docker kill -s SIGHUP prometheus   # 설정 리로드
```

### 4.2 설정 변경 시 반드시 검증 후 반영

`prometheus.yml` 오타 하나로 **Prometheus 전체가 기동 실패하고 재시작 루프**에 빠집니다.
(실제 장애 사례: `metrics_path` → `metric_path` 오타로 전체 다운)

```bash
sudo vi /data/monitoring/prometheus/prometheus.yml
sudo docker exec prometheus promtool check config /etc/prometheus/prometheus.yml   # ← 필수
sudo docker restart prometheus
```

### 4.3 Grafana는 에어갭 전용 설정이 걸려 있음

```yaml
environment:
  - GF_INSTALL_PLUGINS=              # 빈 값 유지 (미설정 시 grafana.com 접속 시도 → 기동 타임아웃)
  - GF_PLUGINS_PREINSTALL_DISABLED=true
```

- **대시보드 ID import 불가.** grafana.com에서 JSON을 받아 반입 후 `Dashboards → Import → Upload JSON`
- macOS에서 파일 반입 시 `._datasource.yml` (AppleDouble) 동반 생성 주의 → `yaml: control characters are not allowed` 오류 원인. `ls -la`로 확인 후 삭제

### 5.1 대상별 특이사항

**WAS (앱 계열) — 인프라가 아닌 앱 배포와 엮임**
- `micrometer-registry-prometheus` 의존성이 **`pom.xml`과 `pom_jar.xml` 양쪽**에 필요
  (Jenkins 파이프라인이 `-f pom_jar.xml` 사용)
- `application-prd.yml` 의 `management.endpoints.web.exposure.include` 에 `prometheus` 포함 필수
- → **앱 재빌드·재배포가 필요한 작업.** 인프라 설정만으로 해결 불가

**nginx (.12 / .13)**
- `/app/nginx` 는 소스 컴파일 설치이며 `--with-http_stub_status_module` 미포함
  ```bash
  /app/nginx/sbin/nginx -V 2>&1 | tr ' ' '\n' | grep stub_status   # 결과 없음
  ```
- → stub_status 사용 불가. nginx 재빌드 또는 access log 기반 exporter 우회 필요
- node_exporter(9100)는 배포됐으나 **SG 미개방 상태**

**Kafka (관리형 서비스)**
- 호스트 직접 접근 불가 → 89번에서 클라이언트 방식으로만 수집
- 수집 가능: consumer lag, offset / 수집 불가: JMX·브로커 내부 지표

**Redis**
- 6379 외부 노출을 피하기 위해 **노드별 redis_exporter(9121)** 방식 채택

## 6. 방화벽(SG) 정책 — ⚠️ Pinpoint와 방향이 정반대

| 제품 | 방식 | 인바운드를 여는 쪽 |
|---|---|---|
| **Pinpoint** | push (Agent → Collector) | **88번(수집 서버)** |
| **Prometheus** | **pull (Prometheus → 대상)** | **각 대상 서버** |

신청 형식: `10.194.178.89 → <대상 IP> / TCP <exporter 포트> (inbound to 대상)`

도달성 확인:
```bash
# 89번에서 실행
nc -zv 10.194.178.12 9100
nc -zv 10.194.178.71 8080
```

## 7. 신규 타겟 추가 절차

```
① 대상 서버에 exporter 기동 (또는 앱에 actuator 노출)
② 대상 서버 로컬에서 curl 로 /metrics 응답 확인
③ SG 신청: 89 → 대상 / exporter 포트
④ 89번에서 nc -zv 도달성 확인
⑤ prometheus.yml 에 job 추가
⑥ promtool check config  ← 생략 금지
⑦ sudo docker restart prometheus
⑧ Status → Targets 에서 UP 확인
⑨ Grafana 대시보드 연결
```

**job 작성 예시** (들여쓰기·라벨 규칙 준수)

```yaml
  - job_name: 'node'
    static_configs:
      - targets: ['10.194.178.12:9100']
        labels:
          instance_name: 'web-front-12'
          application: 'wcs'          # Grafana 대시보드 호환용
```

> `metrics_path` 철자 주의 (기본값 `/metrics` 외의 경로일 때만 명시)
