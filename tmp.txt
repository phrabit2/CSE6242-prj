GPU 서버(10.194.179.86) 작업별 수행 방법 인수인계
A. vLLM — 모델 서빙 (추론)

목적: 학습된/원본 Qwen2.5-VL 모델을 OpenAI 호환 API로 서빙.

실행 방법 (~/vllm/start_vl.sh 기준):

bash
sudo docker run -d --name vllm \
  --gpus all --ipc=host \
  -v /data/ai-models:/models \
  -p 8000:8000 \
  -e HF_HUB_OFFLINE=1 -e TRANSFORMERS_OFFLINE=1 \
  vllm/vllm-openai:<버전> \
  --model /models/Qwen2.5-VL-7B-Instruct \
  --served-model-name qwen2.5-vl \
  --gpu-memory-utilization 0.28 \
  --max-model-len 16384 \
  --limit-mm-per-prompt '{"image":2,"video":0}' \
  --trust-remote-code

핵심 포인트:

모델은 -v /data/ai-models:/models로 마운트, 컨테이너 안에선 /models/... 경로로 참조.
--gpu-memory-utilization 0.28: GPU 메모리의 28%만 사용(나머지는 학습용 확보). 상황에 맞게 조정.
에어갭이므로 HF_HUB_OFFLINE=1 필수.
이름 충돌 시(container name already in use): sudo docker rm -f vllm 후 재실행.

접속 (오피스PC 등 로컬에서):

bash
ssh -o HostKeyAlgorithms=+ssh-rsa -L 8000:localhost:8000 wcsadmin@10.194.179.86
# → 브라우저/API에서 localhost:8000 (OpenAI 호환 엔드포인트)

검증: sudo docker logs vllm / sudo cat ~/vllm/start_vl.sh로 실제 옵션 확인.

B. 커스텀 PyTorch — 학습 (벤치마크용)

목적: LoRA 등 파인튜닝 기법별 자원(GPU/VRAM)·시간 측정. 조건을 직접 통제.

환경: 호스트 conda base (torch 2.11.0+cu128)

bash
source /home/wcsadmin/miniconda3/bin/activate

디렉토리: /data/sample_train/

data/       이미지 + annotation.json + train.jsonl (변환 데이터)
src/        prepare_data.py, train_lora.py, bench.py, monitor.sh
outputs/    학습 결과 (기법/배치별)
results.csv 벤치마크 집계

수행 절차:

데이터 준비: annotation.json → prepare_data.py → train.jsonl (파손 유무 예/아니오 라벨 추출)
모니터링 시작: ./src/monitor.sh <method> (GPU/CPU 시계열을 CSV로 기록)
학습 실행 (시간·CPU메모리 측정 래핑):
bash
   /usr/bin/time -v python3 src/train_lora.py --batch_size <N> 2> outputs/<method>/time.txt
모니터링 종료: ./src/stop_monitor.sh <method>
결과 확인: results.csv (기법·배치별 peak VRAM, 시간, throughput)

측정 항목: peak VRAM(bench.py, torch 내장), GPU/CPU 시계열(nvidia-smi), wall-clock·최대 RSS(time -v).

주의: 벤치마크는 조건 고정이 핵심. batch size만 변경(1/3/5/10/30), epoch=3·gradient accumulation=1 고정. 학습 전 vLLM 중지 권장(sudo docker stop vllm).

검증: ls /data/sample_train/src/, cat /data/sample_train/results.csv

C. LLaMA-Factory — 학습 (GUI/CLI, Docker)

목적: 프레임워크 기반 파인튜닝. WebUI(GUI) 및 CLI 지원. 상사 지시로 도입.

환경: Docker 컨테이너 (호스트 base와 격리)

이미지: hiyouga/llamafactory:latest (에어갭 반입: docker pull --platform linux/amd64 → docker save → 반입 → docker load)

실행 방법 (/data/llamafactory/start.sh):

bash
sudo docker run -d --name llamafactory \
  --gpus all --ipc=host \
  -p 7860:7860 \
  -v /data/ai-models:/models \
  -v /data/sample_train:/data/sample_train \
  -v /data/llamafactory/output:/output \
  -v /data/llamafactory/dataset_info.json:/app/data/dataset_info.json \
  -e GRADIO_SERVER_NAME=0.0.0.0 -e GRADIO_SERVER_PORT=7860 \
  -e HF_HUB_OFFLINE=1 -e TRANSFORMERS_OFFLINE=1 \
  hiyouga/llamafactory:latest \
  llamafactory-cli webui

※ 마운트 경로는 호스트와 동일하게 통일(/data/sample_train:/data/sample_train) — 경로 불일치로 인한 이미지 로드 실패 방지.

데이터 등록: /data/llamafactory/dataset_info.json에 damage_vl 등록(sharegpt 형식, messages/images 컬럼). 데이터는 annotation.json → llamafactory_train.json으로 변환.

학습 방법 1 — WebUI (GUI):

bash
# 로컬에서 터널링
ssh -o HostKeyAlgorithms=+ssh-rsa -L 7860:localhost:7860 wcsadmin@10.194.179.86
# → 브라우저 localhost:7860
Model path에 로컬 경로 /models/Qwen2.5-VL-7B-Instruct 직접 입력(드롭다운 HF 경로 무시).
Dataset: damage_vl 선택. Output dir은 절대경로 /output/...로 지정.

학습 방법 2 — CLI (YAML):

bash
sudo docker exec -it llamafactory llamafactory-cli train /data/sample_train/train_damage.yaml

YAML 주요 항목: model_name_or_path(/models/...), finetuning_type(lora), template(qwen2_vl), dataset(damage_vl), output_dir(/output/...), batch_size, epochs, lora_rank 등.

주의:

output_dir은 반드시 절대경로 /output/... (상대경로 시 컨테이너 내부에 저장돼 유실).
WebUI Model name 드롭다운은 HF 카탈로그 표시용 → 실제 로드는 Model path 값이 결정.
학습은 컨테이너 내부에서 수행, 산출물은 마운트를 통해 호스트 /data/llamafactory/output/에 저장.

산출물: LoRA 어댑터(adapter_model.safetensors, adapter_config.json), trainer_state.json(loss/시간), 토크나이저 파일 세트. 어댑터는 베이스 모델과 세트로 사용.

검증: cat /data/llamafactory/start.sh, sudo docker exec llamafactory cat /app/data/dataset_info.json | grep damage_vl

D. Label Studio — 라벨링

목적: 원본 이미지에 파손 영역을 박스로 라벨링하여 학습 데이터 생성.

접속:

bash
ssh -o HostKeyAlgorithms=+ssh-rsa -L 9080:localhost:9080 wcsadmin@10.194.179.86
# → 브라우저 localhost:9080

라벨링 방식:

라벨 종류: damaged area(파손 영역), product area(제품 영역) — rectangle(bbox)
파손 이미지: 파손 부위에 damaged area 박스 지정
정상 이미지: damaged area 없이 처리(파손 없음 = "아니오" 정답)
태스크 정의: 파손 유무 Y/N 분류 (bbox 유무로 판정)

결과 추출 & 활용:

Label Studio에서 annotation을 JSON으로 export → annotation.json
변환 스크립트로 학습용 데이터 생성 (파손 유무 예/아니오 라벨 추출)
이미지 경로는 학습 환경(호스트/컨테이너)에 맞게 매핑

주의:

Label Studio export의 이미지 경로는 LS 내부 경로(/data/upload/...) → 실제 학습 시 서버 경로로 매핑 필요.
파일명에 LS 업로드 해시 접두어가 붙을 수 있음(변환 시 처리).

검증: 컨테이너 상태 sudo docker ps | grep label, 접속 확인.
