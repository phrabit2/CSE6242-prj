해결 — 네트워크를 명시해서 직접 실행

pinot-init의 compose 정의에 의존하지 말고, collector가 붙어있는 그 네트워크에 직접 붙여서 테이블을 만들자. 이게 가장 확실해.

먼저 그 네트워크 이름 확인:

bash
sudo docker inspect pinpoint-collector --format '{{range $k,$v := .NetworkSettings.Networks}}{{$k}}{{end}}'

나온 네트워크명(아마 pinpoint-docker_pinpoint)으로, pinot-init이 하던 작업을 직접 실행:

bash
sudo docker run --rm \
  --network pinpoint-docker_pinpoint \
  -v /data/pinpoint/pinot-schemas:/schemas:ro \
  apachepinot/pinot:1.0.0-11-amazoncorretto \
  bash -c 'cd /tmp && cp /schemas/*.json . && sed -i "s/localhost:19092/pinpoint-kafka:9092/g" *.json &&
  for t in uriStat tag double dataType exceptionTrace inspectorAgent inspectorApplication; do
    echo "=== AddTable: $t ===";
    /opt/pinot/bin/pinot-admin.sh AddTable -schemaFile ${t}Schema.json -tableConfigFile ${t}Table.json -controllerHost pinot-controller -controllerPort 9000 -exec || true;
  done'

⚠️ 위 --network 값은 첫 명령 결과로 정확히 바꿔줘. collector가 실제로 붙어있는 네트워크여야 pinot-controller 이름이 해석돼.

실행하면 각 테이블마다 === AddTable: uriStat === 뒤에 성공/실패가 찍혀. 이번엔 같은 네트워크라 UnknownHostException 없이 붙을 거야.

확인
bash
curl -s http://localhost:9000/tables
